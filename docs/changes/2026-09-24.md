## 2026-09-24 速度口径调查与修正

- 生产库对照确认：旧口径 `tokens / (completed_at - first_token_at)` 排除了首字前的思考/排队，
  gpt-5.6-luna 当前聚合约 91.4 t/s、完整请求约 22.8 t/s（约 4.0 倍虚高）；
  gpt-5.6-sol 约 60.9 对 12.9 t/s（约 4.7 倍虚高）。
- `avg_by_model` 旧逻辑优先选有 `first_token_at` 的行，会丢掉没有首字时间但实际耗时较长的请求，
  进一步放大速度；生产数据中 sol 最近 8 条有 7 条没有首字时间，luna 有 4 条没有。
- 速度口径统一为 `(output_tokens + reasoning_tokens) / (completed_at - started_at)`：
  包含首字前思考/等待，贴近用户从发起请求到看到完成回复的体感；缺时间戳才回退 duration_ms。
  `calc`、`avg_by_model`、今日平均、会话速度均同步，首字时间只保留作为 TTFT 辅助展示。
- self-check 增加回归：首字后 1s、完整请求 10s 的 500 token 必须显示 50 t/s，不能显示 500 t/s；
  无首字记录也纳入模型聚合。
- 生产回归：luna 约 34.3 t/s、sol 约 12.5 t/s，今日平均约 23.7 t/s；与完整请求耗时口径一致。
- 口径边界：一轮 agent 对话中模型请求之间的工具执行时间不属于某个模型请求，未硬塞进模型 t/s；若要展示整轮端到端效率，应单独用 `turn_usage` 的整轮 token/耗时指标，不能与模型吞吐混用。
