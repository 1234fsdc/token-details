## native 运行中速度误归零修复

- 用户反馈：ZCode 会话仍显示“工作中”，但 Token Details overlay 显示 `0 t/s`。确认这是 bug，不是既定设计。既定口径仍保持为最近 8 条已完成请求的加权速度，不新增伪实时流式计数。
- 根因：`SessionSpeed()` 只读取已完成 `model_usage`；运行中的 assistant 请求尚未落库。旧 `BindTick()` 又在最近完成和 `part` 活动均超过 90 秒时直接清空历史速度，而没有检查同一 session 是否仍有未结束 assistant 回合。真实日志曾记录 `90s空闲归零 ...` 后紧接 `tps=0`。
- 修复：新增 session/model 范围的只读运行请求查询（assistant、`finish IS NULL/'started'`、30 分钟创建窗口、无匹配 usage），只在已有历史速度时跳过错误的 90 秒清零；首次请求无历史仍保持 `0`，运行消息结束/写入 usage 或超过 30 分钟后保护消失。未复用全局 `RunningModels()`，避免不同 session 的同模型并发串值。
- 同步修正 UIA 首次空标题处理：首次空读沿用最近健康标题并启动 4 秒 TTL，持续空读后仍清空，避免 UIA 短暂毛刺导致瞬时归零。
