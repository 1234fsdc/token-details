# 2026-09-23 变更日志

## 修复：ZCode 数据结构变更后面板失联（运行中模型不显示 + 供应商名错误）

根因是 ZCode 侧数据格式变了三处，面板未跟进：

1. **message 表 JSON 键名改名**：`modelID`/`providerID` → `modelId`/`providerId`。
   面板 `live_model()`/`_last_act()` 只认旧键，判活完全失效——模型跑到 90 秒
   窗口外后整行消失（用户截图：nex 在跑但面板只有旧 dots-3 行）。
   - `running_models()`（原 `live_model`）与 `_last_act()` 改为 COALESCE 两种键名都认。

2. **供应商配置搬家**：名称迁入 `~/.zcode/v2/provider_config.json`
   （`config.providerConfigRules.providerRules[]` 的 `providerId`/`providerName`），
   旧 `v2/config.json` 已删除。`provider_names()` 增加新结构解析（保留旧结构兼容）。
   修复前先退化成 `new-prov`。

3. **运行中判定升级**（顺带修"统计不准确"）：
   - 旧逻辑只看"最新一条 assistant 消息"，并发多会话只能显示一个，长工具调用
     间隙还会误判掉线。
   - 新逻辑 `running_models(db)`：`finish` 为空或 `started` = 仍在流式生成，按
     (模型, 供应商) 分组逐个列出所有生成中的会话，各自显示"运行中…"。
   - `_last_act()` 改用 `time_updated`（流式/工具调用期间持续刷新）替代
     `time_created`，长回合不会因 created 超过 90 秒被误判不活跃。
   - 实测：并发跑 nex + Qwen 两会话时两行同时显示；供应商正确解析为 AMD/Kilo。

`live_model` 无其他调用方，直接改名 `running_models`；self-check 同步重写
（新增 finish 判据、并发多会话、time_updated 长回合、新旧键名用例）。
重新打包 dist/TokenDetails.exe。

## 追加修复：思考/长回合阶段运行中模型仍会消失

v1.1.0 的 finish 判据依赖 `time_updated` 90 秒窗口，但 ZCode 在模型"思考"
（reasoning）阶段不写流式 token，消息行不再刷新——长思考超过 90 秒行就消失
（用户截图：nex 正在思考，面板没有它的行）。

库结构实测（2026-09-23）：
- ZCode 每次模型请求**结束**时才往 model_usage 落行（completed/error/cancelled
  三种终态都有），运行期间不落；单次请求最长约 5.5 分钟。
- model_usage.id 嵌 message.id（`usage_model_main_turn_<msg_id>_0`），可精确对应。

`running_models()` 判据改为：assistant 消息 `finish` 为空/'started'，且
`model_usage` 中不存在对应 id 的行 = 正在运行（思考/生成/工具间隙全阶段成立）。
30 分钟仍无 usage 行视为崩溃遗留僵尸行，不再显示"运行中"（全库 52 条
finish=NULL 行验证：仅 1 条真运行中 + 3 条 7 小时以上僵尸）。
self-check 同步补：结束回合（finish 落定+usage 行出现）立刻不显示、僵尸行、
并发多会话用例。
- 提交后重新打包，覆盖 v1.1.0 Release 附件（--clobber），更新说明 SHA256。

## 追加优化：运行中也显示速度数字（用户 2026-09-23 产品要求）

"运行中…"静止文字让人误以为面板坏了。但生成期间无任何实时 token 计数可测速
（实测：message 行 tokens 恒 0 直到结束、model_usage 结束才落行、主日志事件均为
完成时刻、rollout 整条完成后落盘），真实时测速无原料。

显示方案（用户定稿：不加 ≈、不显示"运行中"文字，运行中行与完成行完全同样式）：
运行中行数字 = 该模型最近 5 次加权均速（回合结束即替换为真实值，界面无差别），
时刻 = 本次请求开始时间；该模型无历史（首次请求）时数字位显示"…"置灰。
运行中优先于同模型刚完成的旧速度行（否则运行中显示的会是上一轮数字）。
- `running_models()` 增加 `started`（最早未结束请求的 time_created）。
- `detail_data()` 运行中分支带 `tps=均速`（无历史则 "…"）。
self-check 同步 `started` 字段断言。

## 追加：无回报模型按 part 字符估算 token（用户定稿：仅 silent 模型）

Agnes 供应商 API 不回报输出 usage（agnes-3.0-flash 266 条记录 output+reasoning
合计 299 tok，≈每次 1 个；turn_usage/message 同样全 0）→ 历史与运行中速度
都算不出。深挖发现 `part` 表（消息正文分段）生成期间约 2 秒/次实时写入，
正文与工具调用参数可数——提供估算原料。

用户决策（2026-09-23）：只给无 token 回报的模型走字符估算，回报正常的模型
保持精确值不变；规则数据驱动，之后任何新模型出现同样情况自动命中。
- `TOK_PER_CHAR=0.6`：对当日回报正常模型标定（0.29~1.6 的中位，约 1.45 字符/token）。
- `_est_map(db, rows)`：窗口内 ≥3 条完成行且输出回报合计 <20 tok = "无回报"
  （agnes 与 deepseek-v4.1 自动命中；换回报正常供应商自动退出）；
  usage.id 内嵌 msg id 关联 part 正文（text + state.input 字符数）。
- `calc/avg_by_model` 加 est 参数：真实回报恒 0 时用估算值；detail_data 每秒
  单帧实测 84ms。有回报模型完全不走此路径。
self-check 补估算用例（silent/report 判定、60tok/条均速、part 缺失退回）。
