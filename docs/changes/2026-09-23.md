# 2026-09-23 变更日志

## 修复：ZCode 数据结构变更后面板失联（运行中模型不显示 + 供应商名错误）

根因是 ZCode 侧数据格式变了三处，面板未跟进：

1. **message 表 JSON 键名改名**：`modelID`/`providerID` → `modelId`/`providerId`。
   面板 `live_model()`/`_last_act()` 只认旧键，判活完全失效——模型跑到 90 秒
   窗口外后整行消失（用户截图：nex 在跑但面板只有旧 dots-3 行）。
   - `running_models()`（原 `live_model`）与 `_last_act()` 改为 COALESCE 两种键名都认。

2. **供应商配置搬家**：名称迁入 `~/.zcode/v2/provider_config.json`
   （`config.providerConfigRules.providerRules[]` 的 `providerId`/`providerName`），
   旧 `v2/config.json` 已删除。`provider_names()` 增加新结构解析（保留旧结构兼容）。
   修复前先退化成 `new-prov`。

3. **运行中判定升级**（顺带修"统计不准确"）：
   - 旧逻辑只看"最新一条 assistant 消息"，并发多会话只能显示一个，长工具调用
     间隙还会误判掉线。
   - 新逻辑 `running_models(db)`：`finish` 为空或 `started` = 仍在流式生成，按
     (模型, 供应商) 分组逐个列出所有生成中的会话，各自显示"运行中…"。
   - `_last_act()` 改用 `time_updated`（流式/工具调用期间持续刷新）替代
     `time_created`，长回合不会因 created 超过 90 秒被误判不活跃。
   - 实测：并发跑 nex + Qwen 两会话时两行同时显示；供应商正确解析为 AMD/Kilo。

`live_model` 无其他调用方，直接改名 `running_models`；self-check 同步重写
（新增 finish 判据、并发多会话、time_updated 长回合、新旧键名用例）。
重新打包 dist/TokenDetails.exe。
